# 给 DSH 的传奇任务：Metropolis Council

你是一个自主研发团队的首席游戏程序员、城市模拟设计师、3D 美术总监和 benchmark 工程师。请在当前工作目录完成真正可运行、可玩的开源项目，不要只写产品策划或 demo 假画面。先读本包的调研报告和评测方案。你有权限在许可范围内查阅、下载及复用代码/资源，并进行必要的终端命令、编译、测试和迭代。遇到环境或时间限制时自主选择降级路径，优先留下真实可运行成果、明确剩余工作，不要用占位按钮冒充实现。

## 产品愿景

做一款高自由度、3D 城市经营与治理游戏：从随机地形上的小镇成长为超级大都会，也可能由于财政危机、基础设施和人口流失而破产。宏观体验达到商业城市建造游戏的吸引力与丰富感；玩家是市长/城市规划者，提出政策、预算、发展目标、优先级与区域意向，不需要手工修每条路。复杂的市政 council 与城市部门负责自动规划、建设与日常治理。游戏离线完全可玩，规则 council 是默认；玩家可配置 OpenAI-compatible API，让 LLM 担任议员并产出受约束提案。

**两个不同目标均需交付**：一是能让人愿意持续玩的游戏；二是为研究者提供可以比较不同 LLM 的公平、可复现的长期城市治理 benchmark。不要通过堆文字、改变外观或假数据制造复杂性。

## 首先验证选型并立即动手

1. 检查当前环境（OS、CPU/GPU、网络、可用工具、是否已有仓库），记录结果。优先拉取 Egregoria 固定 commit 并阅读 LICENSE、架构、asset 清单，尝试构建、启动、固定种子模拟及最小修改，时间有上限。评估自动生成路网和外部控制接口改造成本。每个来源记录 URL、commit/版本、许可证和适用文件。
2. 如果 Egregoria 能构建且适配，就 fork，保留原版权、GPL 条款、修改记录和源码；若不可行，用有确切许可证的替代或自主开发。推荐自主备选 Rust/Bevy 或 TypeScript/Three.js（按运行环境选），要求 headless 与渲染分离。给出理由，不得声称未执行的命令通过。不要在启动时依赖付费 API。
3. 迅速交付一个 end-to-end 可玩垂直切片：随机地图→自动建路与住房→居民迁入和就业→财政/水电→可视反馈→模拟若干年→破产/里程碑→保存与重放。然后再扩展，最后做精致化和 benchmark。任何阶段如果受阻，保留可启动版本及准确的阻塞报告。

## 游戏体验与内容

- 地图以 seed 驱动：高程、河流/海岸、水资源、森林、矿物、平地、可达性和有限土地。生成失败自动重试并保证初始位置可通行。提供多个种子和难度；看得出不同地形的运营差异。
- 玩家设置税率、服务等级、建设/维护预算、举债、城市发展方向、环境与公平优先级，可设置扩张区和审批阈值。默认 council 可在授权预算内自动施工，重大债务、过预算、变更战略须玩家批准。可暂停、加速、观察并回滚未提交提案。
- 人口需具有年龄/家庭、住所、就业或教育、收入、健康、需求、幸福、通勤与迁移状态。使用确定性有限状态或效用规则，无需逐人调用 LLM；随机流分组，明示人口扩展/抽样方式，不把代表样本谎称逐人模拟。
- 制造可观察的完整经济闭环：税源、企业、住房、就业、建设费、维护费、服务费、债务、利息、进出口或资源短缺、收入支出平衡。确保钱与实物流入/消耗在总账可追踪，禁止无记录地凭空补贴。
- 工业、商业、居住发展相互影响，至少实现供水/污水、电力、垃圾、医疗、教育、消防、基础公共交通与污染中的一组能产生真实因果作用的系统。所有未实现系统明确列为未完成，不能作为已完成宣传。考虑地形、网络和区位决定建设成本及服务覆盖。
- 自动空间设计：道路网络图；基于可达、坡度、交叉、与中心的连通性、预算以及环境冲突生成多个可行候选；针对可建设地切分地块，规划分区和设施，依照 demand、通勤和服务容量建设。实现碰撞/水体/坡度/连接验证，展示工程预算、影响和解释，避免每 tick 随机铺路。
- 交互式 3D 可视化：缩放、旋转和平移；有真实地形、河流、道路、行人/车辆、现代建筑群、昼夜/光影、绿地、建筑风格与地标层次；建设后画面可见变化；财政、交通、污染等叠图清晰。逐步替换占位模型，细节尽力追求接近《城市：天际线》的完成度，但使用原创或经授权资源，不复制其模型、纹理、音效、UI 和商标。高质量不是数量承诺；汇报真实画面及仍欠缺之处。
- UI 里显示城市核心状态、收支、需求、未满足服务、交通、风险和 council 日志。适当设计有取舍的事件链与可解释的警报，玩家可以理解行动为什么造成后果。设置可达成的胜利里程碑和清晰、可恢复或最终破产条件；提供新手教程和试玩场景。

## Council 与模型接入

至少规划、财政、交通、民生、产业/环境等职责；每期部门拿到明确的局部事实、预算和公共目标，规则产生带预期代价/收益/风险/冲突的候选；一个确定性裁决器在约束内排序决策，记录被拒原因。为玩家提供建议、委托、审批三模式，权力边界清楚。不要让模型通过自然语言直接更改 WorldState 或执行 shell。

可选 LLM 接入：可配置 base URL、model、API key、超时、最大调用频率、token 上限、费用上限；使用服务端代理/本地配置，不将密钥写入源码、游戏存档、日志、浏览器客户端或提交。请求失败、429、返回非 JSON 或 schema 错误，先有限重试再 deterministic fallback；提示文本和外部内容视为不可信数据。模型只能输出 `proposal_id, role, observations, actions[], expected_cost, rationale, uncertainty` 等有界数据。所有动作经过业务校验，拒绝非法区域、不存在资源、越权、超预算及非白名单操作。任何 LLM 不可影响模拟器内部事实、评分器或伪造统计。

## 工程要求

核心固定 tick 与表现层、随机数来源、调度器和数据持久化分开。所有动作经过同一命令队列，包括 GUI、规则代理和 LLM。每个事件携带时间、actor、前后状态摘要、资金/资源变化、拒绝原因；save/load 保留 schema version、世界 seed、RNG 状态、动作历史、commit/version 和校验和。headless 可从固定配置运行不依赖渲染，支持快照、导出 JSONL 与 CSV。为性能设基准并如实测量（tick/s、帧率、内存、人口数量、机器配置）；使用分块/批处理/缓存/LOD 而非无依据承诺十万人实时模拟。

设计清晰目录，提供可一键启动的本地方式、配置样例、开发说明和架构图。锁定依赖、制定第三方资源/代码来源表与许可文件。控制数据使用权，不把商业游戏本体或未知许可内容打包。对 AI 生成内容记录工具与许可来源，不承诺用户无条件拥有工具产物权利。若派生 GPL/AGPL 代码，遵守相应条款及提供源码义务，不自称 MIT-only。

## Benchmark 要求

实施随包 `03_评测方案.md`，至少：确定性 headless runner；固定规则 baseline（无行动、财政贪心、合理 rule council）；分开的市长和议会赛道；scenario/seed 配置；预算/调用次数约束；原始指标与评分函数；逐动作日志；模型配置和费用；可按动作录制回放。使用统一观察、统一 API、同样频率、模型以结构化动作接口控制，严格隔离隐藏未来随机数/内部状态。提供公开开发种子、独立测试种子机制、置信区间统计及失败记录。说明 replay 的确定性仅限已记录动作；远端模型重复调用不保证相同。

必须有实际运行结果：同一场景对至少 3 种 baseline 进行多 seed headless 测试，报告指标、失败率及耗时。若无可用 API，做可复现的 mock API/协议测试，不虚报任何真实模型结果。早期分数标示为实验性；不能把游戏表现外推为真实城市治理能力。

持续实现直到全部可运行范围完成；不要为了篇幅只给计划。创建 TODO 并持续更新，先跑通再扩展。最终提供：
