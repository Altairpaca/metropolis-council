# City Governance Benchmark v0.1（提案，数值待实测校准）

## 范围和实验单元

评估模型在模拟世界中依据有限信息做长期决策的能力，而非城市规划专业资质。一个 episode = (模拟器版本, 场景配置, 世界种子, 模型/代理, 预算, 最大决策轮次, 重复编号)。环境固定随机源并分离地形、事件、人口、经济 RNG，按事件时间预生成外生冲击，防止不同策略的调用顺序改变冲击；若确有行动依赖随机性，使用稳定事件 ID 及反事实可对齐的随机流。

两个赛道：Mayor track 被测模型作市长，固定规则 council 执行；Council track 玩家/市长目标由固定脚本给出，被测模型扮演 council，固定裁决器。其他条件相同。另可增加 multi-agent track，但不能拿其更高 token 成本直接与单 agent 视为公平对比。

## 操作协议

每个决策周期对所有代理提供一致可见观测：城市概要、前 N 期汇总、地图聚合、预算/债务、人口与服务、已知风险、候选行动、合法范围与费用公式；隐藏未来冲击、模拟器内部未观测事实和私有 seed。动作是版本化 JSON：政策参数、目标区、服务投入、项目候选、举债等，明确无操作；同一决策频率和最大返回长度；硬校验后执行。规则 council 不得享有比模型更多的信息。调试模式可显示全状态，但成绩必须标记非正式。

同预算主赛道固定观察字段、最大决策调用次数、输入输出 token 限额和决策期限，记录价格、延迟和错误；价格不同可另设货币预算赛道，不能把价格变化混为能力。超过次数或额度停止调用，模型失败视为无行动或既定 fallback 并报告。给每个模型相同的说明、提示模板、工具定义和允许重试策略；记录各模型采样参数、版本、provider、时间、价格依据及完整非敏感交互（如需隐私保护可做受控发布）。

## 场景矩阵（待实现和校准，禁止当成已有测试）

| 场景 | 初始状态与约束 | 突发事件及主要能力 | 衡量焦点 |
|---|---|---|---|
| 起步小镇 | 小预算、足够土地与有限供水；至少 120 月 | 月 30 起人口就业逐步增加；长期规划 | 到期存活率、可持续人口、累计财政 |
| 缺水工业城 | 可建设面积足、水源少、工业需求高 | 旱季供水减少，工业与居民争水 | 供水可靠率、经济产出、健康与污染 |
| 两岸交通 | 河流阻隔、东岸住房西岸就业，桥梁成本高 | 交通需求逐渐上涨 | 通勤、接入率、资本和维护成本 |
| 衰退财政 | 初始债务高且维护欠账 | 税基减少、设施老化 | 债务轨迹、基本服务底线、违约率 |
| 不平等增长 | 两区收入及覆盖差异明显 | 外部投资偏好高收入区 | 全城增长、低收入区覆盖、差距 |
| 复合危机 | 资源适中，有准备期 | 洪水与电力故障连续发生 | 恢复时间、人口损失、韧性成本 |

开发公开种子例如 101–110；最终应在发布时建立分布独立的测试 seed 与未公开参数，预注册生成规则和算法版本，不承诺长期秘密。每项先试跑校准初始条件，确保并非所有 baseline 稳赢或全灭；冻结配置及胜负定义后再正式排名。对所有代理使用配对 seed，多模型之间相同情景/冲击；至少 30 个独立种子作为正式对比起点，依据方差与资源做统计功效规划。试运行数量不足仅做探索结果。

## 指标：完整记录 + 可解释聚合

每回合/episode 输出人口与人口变化、净迁入，住房/就业、通勤时间，财政收支/债务/现金/违约，电水/医疗/教育等服务达标率，污染、健康、满意度、各收入/地区分布，建设/维护投入，灾害损失与恢复时间，非法动作比例、任务完成率、模型成本和延迟。所有百分比写明分母、统计窗口及缺失值处理；死亡/人口迁出后不能通过缩减需求而掩盖服务崩溃。

v0.1 的可比较性样例（阈值**是待注册/校准的游戏参数，不是事实**）：每个指标 `x` 在目标 [bad, good] 线性归一化并截断到 0–100；越低越好先反向。六维分：繁荣 20%（就业与可持续人口等）、财政 20%（生存/偿债/净资产）、基础服务 20%（人口加权供给达标与覆盖）、环境健康 15%、公平 10%（低收入及地区服务差异）、韧性 15%（灾害损失与恢复）。每维内部的组成、权重及 bad/good 阈值必须在配置冻结时显式填写；在此之前不计算排行榜总分。若破产，按完整预设时间窗、失败后的终止值与生存时间计分，禁止事后仅平均存活期以奖励早早失败。硬底线单独报告（破产、长期缺水、服务崩溃），任何加权分不得掩盖。

建议公开：逐指标表、6 维向量、按场景结果、失败率、成本/延迟以及分数；主分不自动扣除美元成本，另报告 cost-efficiency。对配对 seed 的模型差值，用 seed 为单位的 bootstrap 95% CI；二元指标报告适当区间；原始 episode 数据与缺失/错误均保留。不要以显著性或小数位掩盖样本不足。

## Baselines 与消融

- No-op：无新政策，仅游戏默认行为。
- Finance-greedy：只基于可见现金/债务做增税和缩支，不接收隐藏信息。
- Rule council：读取相同观测，按公开阈值和候选评分做规划。
- 视资源增设单次规划、滚动规划、无记忆/无地理输入、单角色与多角色、结构化与文字输入的消融。必须标明调用次数和信息差。

## 可重复性与防污染

固定模拟版本、世界生成参数、时间步、依赖锁、资产版本、schema、配置和种子；存储完整世界快照/RNG 状态、动作顺序和哈希。确定性承诺仅适用于同一受支持执行环境及已录制动作；浮点、并行、CPU 架构差异要实测。LLM 输出本身不可因 seed 自动复现，以动作 replay 恢复相同轨迹。所有错误、超时、拒绝、手动干预单独记录。正式结果不得依靠语言模型自评，不把说明书暴露的信息当隐藏信息。模型知晓公开规则不视作弊；针对过拟合用新种子、新约束、参数分布转移、持出测试与可审计提交协议。沙箱中禁止模型执行任意代码或修改评分。

## 最小验收

至少 3 个基线、3 个场景、每场景 5 个 seed 的可运行 smoke test；不称为正式统计排名。报告随机 seed、执行命令、哈希、版本、真实耗时和逐项结果。模拟 API 错误测试必须和真实 API 结果分列。评分表仅在所需真实指标均实现、公式冻结后公开；未实现项目标记 N/A，不得插值冒充。
