# 开源城市治理游戏与 LLM Benchmark 调研

调查日期：2026-11-09。定位：面向 DSH 的可执行研究与工程决策包；当前为公开文档、论文摘要/方法和部分仓库文件的定向调查，**没有运行或完整审计任何候选项目**。结论需在选型 spike 中复核最新 commit、构建、资产和依赖。来源链接集中于文末。

## 1. 产品判断

做一款从小城成长为大都会的 3D 城市治理游戏：玩家选财政、产业、公共服务和政策方向，市政 council 生成可审计的规划并自动施工；每个市民使用便宜的有限状态/效用规则，LLM 只在市长、部门官员或特殊事件层可选调用。模拟必须离线可玩，LLM 在模拟步之外作提议，严格校验后落地。

最有希望的代码底座是 **Egregoria**：Rust/wgpu、3D 非网格、交通、企业与居民，其架构文档明确描述 fixed tick、确定性模拟、世界命令与渲染分离 [R1,R2]。但它仍处于早期、世界经济简化，不代表现成的《城市：天际线》功能、更不代表本机能构建。先做 1–2 天有时限的 spike，再决定 fork 或自主实现；不应把纸面选型写成已验证事实。

**双重 benchmark**：A. 对 DSH/代码智能体的构建任务（能否实现游戏和实验工具），B. 用最终游戏评测治理模型（在相同城市和预算下谁治理得好）。两者分别记录，禁止将游戏表现宣称为自动验证 DSH 工程能力，更不能声称反映真实城市治理水平。

## 3. UGOD 与研究进展

根据用户说明，本文将 UGOD 用作“城市治理与设计及相关 AI 研究”的工作范围，而非指某篇特定论文或预设该缩写是通行术语。覆盖城市规划、空间模拟、治理决策、生成式智能体和评测；其中 UGI 是具体研究框架，不与 UGOD 等同。

- **UGI / PLOS 2026**：LLM agents、城市模拟和城市知识图谱通过自然语言接口连接，强调城市物理、社会和经济多层关系 [R8,R9]。启示：将 state/tool 接口与认知/模型层解耦，提供结构化世界状态；论文提出框架不等于现实预测已经验证。
- **CityBench / KDD 2025**：CityData、CitySimu、八项感知理解/决策任务，十三座城市 [R7,R10]。启示：任务拆解、不同地图数据和观察模式；它并不直接回答多年闭环财政治理好坏。
- **USTBench**：UAgentEnv 中包含城市决策及预测任务，强调时空推理与过程 [R11]。启示：考察诊断、预测、规划与反思而非只给结果分数。
- **CitySim / EMNLP 2025**：城市图、个体画像、日程、记忆及交通选择 [R12]。启示：模拟人口异质性、日常活动与位置，但本项目保留廉价 rule-based 人口，不强制 LLM per citizen。
- **MobileCity / EACL 2026**：论文报告 4,000 agents 的实验 [R13]。启示：明确规模、算力和成本；不能把其报告直接移植为本项目性能数据。
- **多方规划决策研究**：模拟政府主持、利益相关者表达与投票，并讨论群体意见趋同和幻觉 [R14]。启示：议会要记录角色冲突、证据和异议，玩家保留政策主权；模拟人物不代表真实利益群体。
- **城市治理 life-history benchmark**：探讨居民画像与 token 成本的权衡 [R15]。启示：公开费用及输入信息预算，比较 equal-budget 与 unconstrained 两个赛道。

区别是：这些研究多为城市任务、移动行为或利益相关方对话；本项目拟结合可玩的长期财政闭环、自动空间建设、多目标治理和可复现的模型赛道。这是设计上的差异，并非已经证明学术创新或现实有效。

## 4. 城市天际线公开机制拆解

以一代为主要体验参照，以二代公开开发日志补充，不把两代及 DLC 常量混在一起。官方材料提及财政、交通、供水供电、教育、警消医疗，以及商业、公司、地价、幸福度、经济资源和居民生活轨迹 [R16–R19]。其专有源代码与模型资产没有因支持 mod 而自动开源；此处研究的是公开说明、游戏机制、玩家体验和可独立实现的抽象。

| 系统 | 玩家看到的因果关系 | 本项目的代理实现 |
|---|---|---|
| 地形/土地 | 海岸、河流、坡度与资源影响成本和发展方向 | seeded 高程/水系/可建设地/资源，保证起始可达 |
| 建设/道路 | 可达性影响开发和服务 | 玩家画战略发展区/设预算，council 通过候选评分自动路网和地块，保留预览与审计 |
| 需求/人口 | 住房、就业、税收、服务互相影响 | 人口住址、职业、家庭、需求与迁移，聚合机制明确 |
| 公共设施 | 能力不足导致停水停电、疾病、火灾及不满 | 产能、覆盖、运营支出、排队和容量，数据面板解释原因 |
| 财政 | 基建投资、运营支出、税基、债务与增长互相约束 | 每期总账、建设/维护/债务分别列账；资金不足触发债务/破产流程 |
| 交通 | 规划造成拥堵，影响通勤/运输及效率 | 图寻路、容量、时间与乘客/货流；先宏观流量，逐步叠加 agent |
| 环境/风险 | 产业污染、垃圾、灾害影响健康和用地 | 传播/缓解、风险事件和可见的滞后效果 |
| 视觉/交互 | 连续 3D 街景与可读的统计叠加 | 原创现代写实城市场景、镜头/昼夜/LOD、数据热力图；不能挪用原游戏资源和近似临摹具体资产 |

精确建筑售价、单位、税率和各版本人口阈值当前未逐项验证；不要伪称复刻原作精确参数。先制订自洽游戏单位并让每个参数注明来源/假设；建立可调整平衡配置。官方《二代》交通说明特别强调路径选择和多核成本 [R18]；经济 2.0 改动表明版本变更能改变租金、教育与需求 [R19]。

## 5. 技术结构及 LLM 边界

核心 `WorldState` 由固定 tick 的确定性事务更新，分地形/路网、资源、经济、人口、服务、事件与统计。模拟器提供 headless CLI，3D 只是订阅同一状态；资源账本、策略和已执行 command 可序列化。人为输入、council 规则、LLM 动作都走同一验证器与命令队列。角色分工：规划、财政、民生、交通、产业、环境；每位先给结构化提案，确定性裁决器检查预算、地理、权责，给玩家预览/高层委托及事件日志。有限候选清单与 deterministic fallback 确保没有 API 时正常可玩。

LLM 通过服务端或本地代理对 OpenAI-compatible Chat Completions API 接入，自定义 base URL/model/key，禁止浏览器打包 key。其输出不是代码或任意 shell：仅接受带 schema 的白名单计划、预算、置信和理由，拒绝非法坐标、超支、虚构数值；超时、错误、429 回退规则。对于治理 benchmark，不能将被测模型的隐藏推理或未经验证的自评分当指标。记录 model ID、版本、参数、请求时间、token、延迟、错误和价格假设；默认敏感数据脱敏。相同随机种子只能保证环境/重放，而不能保证远端 LLM 重复输出。

## 6. 基准设计摘要

详见 03_评测方案.md。以增长、稳定、服务、环境、韧性、预算六维呈现，报告各项原始量与达标率，不用人口单项充当胜利。规则规划器、无行动、贪心财政分别作基线；将 Mayor 模型与 Council 模型分赛道，固定另一端以免混淆。所有提交必须留存动作、世界版本、评测 seed、事件序列、token 和成本；保留私有测试种子但公开生成程序和 schema。试验均为模拟器内能力，不视为对现实政策的因果预测。

## 7. 美术与开源约束

用户要求接近一比一视觉完成度，研发目标应解释为**相近的精细程度、材质与视距体验**，不复制特定建筑模型、纹理、UI、音效、标志、原作数据包或识别性构图。Kenney 城市资源包是 CC0 [R20]，易于搭原型但偏卡通；Poly Haven 宣称其资产 CC0 [R21]，适合材质/HDRI，仍须核对每项来源、人物和标识。程序化模块化建筑、独立生成 3D 或自行建模，记录工具/版本/生成记录、第三方许可及来源；生成结果也需审查近似性与工具条款。图片生成模型通常只给 2D，不能假定可直接产出可用低面数 3D 模型。将素材账本与代码许可证分离。不要使用无再分发授权的下载模型。

## 8. 不确定性及接下来

仓库仍会变动；本次未实机测 Egregoria 的 build、地图、scale 或资产许可证，亦未阅读封闭商业游戏代码；对研究主要基于原论文摘要/方法与仓库文档，非系统性综述。下一步由 DSH 检出固定 commit、测试干净构建及许可证，给出 go/no-go 后完成垂直切片。后续可继续针对城市设计、土地利用优化与多目标规划补充更系统的文献综述。
